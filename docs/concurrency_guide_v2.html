Threads (Low-Level)

A thread is the smallest unit of execution within a process. Think of it as a worker that can run code independently.

What is a Thread?

  • A thread runs inside a process (your Python program)
  • Multiple threads share the same memory space
  • Each thread can execute code independently
  • Python's threading module provides thread support
Process vs Thread
+------------------------------------------+
|           PROCESS (Your Python App)      |
|  +------------------------------------+  |
|  |         SHARED MEMORY              |  |
|  |   (variables, data structures)     |  |
|  +------------------------------------+  |
|                                          |
|  +---------+ +---------+ +---------+     |
|  | Thread 1| | Thread 2| | Thread 3|     |
|  | (Main)  | | (API 1) | | (API 2) |     |
|  +---------+ +---------+ +---------+     |
+------------------------------------------+

Basic Thread Example

import threading
import time

# This function will run in a separate thread
def fetch_data(name, seconds):
    print(f"{name}: Starting...")
    time.sleep(seconds)  # Simulates API call
    print(f"{name}: Done after {seconds}s")
    return f"Result from {name}"

# Create threads
thread1 = threading.Thread(target=fetch_data, args=("RTC", 2))
thread2 = threading.Thread(target=fetch_data, args=("JIRA", 3))
thread3 = threading.Thread(target=fetch_data, args=("Azure", 1))

# Start all threads (they run in parallel)
thread1.start()
thread2.start()
thread3.start()

# Wait for all threads to complete
thread1.join()
thread2.join()
thread3.join()

print("All done!")
RTC: Starting... JIRA: Starting... Azure: Starting... Azure: Done after 1s RTC: Done after 2s JIRA: Done after 3s All done!

Problem: How to Get Return Values?

Notice that fetch_data returns a value, but we can't easily get it! Threads don't have a built-in way to return values. You need workarounds like global variables or queues.

Getting Return Values (The Hard Way)

import threading

results = {}  # Shared dictionary to store results

def fetch_data(name, seconds):
    time.sleep(seconds)
    results[name] = f"Result from {name}"  # Store in shared dict

threads = []
for name, sec in [("RTC", 2), ("JIRA", 3)]:
    t = threading.Thread(target=fetch_data, args=(name, sec))
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print(results)  # {'RTC': 'Result from RTC', 'JIRA': 'Result from JIRA'}

Pros

  • Full control over thread lifecycle
  • Good for long-running background tasks
  • Can be used for any concurrent task

Cons

  • Manual thread management
  • No easy way to get return values
  • Risk of race conditions
  • Need to handle thread cleanup

Executors & Futures (High-Level)

Executors are a higher-level abstraction that manage threads for you. They solve the problems of raw threads!

What is an Executor?

  • ThreadPoolExecutor: Manages a pool of reusable threads
  • Future: A placeholder for a result that will be available later
  • Automatically handles thread creation and cleanup
  • Easy way to get return values via .result()
How Executor Works
     YOUR CODE                    EXECUTOR                    THREADS
         |                            |                          |
         |  submit(func, args)        |                          |
         | -------------------------> |                          |
         |                            |  assigns to thread       |
         |  <--- Future (receipt)     | -----------------------> |
         |                            |                          | runs func()
         |                            |                          |
         |  future.result()           |                          |
         | -------------------------> |  <---------------------  | returns value
         |  <--- actual result        |                          |
Future = Restaurant Receipt

You order food -> You get a receipt (Future)

Kitchen is cooking -> Receipt exists, food not ready (future.running())

Food is ready -> Exchange receipt for food (future.result())

Basic Executor Example

from concurrent.futures import ThreadPoolExecutor
import time

def fetch_data(name, seconds):
    print(f"{name}: Starting...")
    time.sleep(seconds)
    return f"Result from {name}"  # Can return values easily!

# Create executor with 3 worker threads
with ThreadPoolExecutor(max_workers=3) as executor:
    # Submit tasks - returns Future objects immediately
    future1 = executor.submit(fetch_data, "RTC", 2)
    future2 = executor.submit(fetch_data, "JIRA", 3)
    future3 = executor.submit(fetch_data, "Azure", 1)
    
    # All 3 are running in parallel right now!
    print("Tasks submitted, doing other work...")
    
    # Get results (blocks until ready)
    print(future1.result())  # "Result from RTC"
    print(future2.result())  # "Result from JIRA"
    print(future3.result())  # "Result from Azure"
Tasks submitted, doing other work... RTC: Starting... JIRA: Starting... Azure: Starting... Result from RTC Result from JIRA Result from Azure

Future Object Methods

future = executor.submit(some_function, arg1, arg2)

# Check status
future.done()       # True if completed (success or failure)
future.running()    # True if currently executing
future.cancelled()  # True if was cancelled

# Get result
future.result()              # Blocks until done, returns value
future.result(timeout=10)    # Wait max 10 seconds

# Cancel (only works if not started yet)
future.cancel()

Using as_completed() - Process Results As They Finish

from concurrent.futures import ThreadPoolExecutor, as_completed

def fetch_data(name, seconds):
    time.sleep(seconds)
    return {"name": name, "data": f"Result from {name}"}

with ThreadPoolExecutor() as executor:
    # Map futures to their metadata
    future_to_name = {
        executor.submit(fetch_data, "RTC", 3): "RTC",
        executor.submit(fetch_data, "JIRA", 1): "JIRA",
        executor.submit(fetch_data, "Azure", 2): "Azure",
    }
    
    # Process results as they complete (fastest first!)
    for future in as_completed(future_to_name):
        name = future_to_name[future]
        result = future.result()
        print(f"{name} finished: {result}")
JIRA finished: {'name': 'JIRA', 'data': 'Result from JIRA'} # 1 second Azure finished: {'name': 'Azure', 'data': 'Result from Azure'} # 2 seconds RTC finished: {'name': 'RTC', 'data': 'Result from RTC'} # 3 seconds

Why as_completed() Matters

Without as_completed(): You wait for results in submission order. If first task takes 10s and second takes 1s, you wait 10s before seeing any result.

With as_completed(): You get results as soon as they're ready. The 1s task result comes first!

Handling Timeouts and Errors

from concurrent.futures import ThreadPoolExecutor, as_completed, TimeoutError

with ThreadPoolExecutor() as executor:
    futures = {
        executor.submit(fetch_data, "RTC", 2): "RTC",
        executor.submit(fetch_data, "JIRA", 100): "JIRA",  # Very slow!
    }
    
    for future in as_completed(futures, timeout=30):
        name = futures[future]
        try:
            result = future.result(timeout=5)
            print(f"{name}: {result}")
        except TimeoutError:
            print(f"{name}: Timed out!")
        except Exception as e:
            print(f"{name}: Error - {e}")

Pros

  • Easy to get return values
  • Automatic thread management
  • Built-in timeout support
  • Context manager handles cleanup
  • Thread pool reuses threads efficiently

Cons

  • Still uses threads (GIL limitation)
  • Not ideal for CPU-bound tasks
  • Slightly more overhead than raw threads

Async/Await (Single-Threaded Concurrency)

Async is a completely different approach - it achieves concurrency with a single thread using cooperative multitasking.

What is Async?

  • Uses a single thread with an event loop
  • Tasks voluntarily yield control when waiting (I/O)
  • async def defines a coroutine (async function)
  • await pauses execution and lets other tasks run
  • Best for I/O-bound tasks (network, file, database)
Single Chef, Multiple Dishes

Threads: 3 chefs, each cooking one dish

Async: 1 chef cooking 3 dishes - while dish 1 is in the oven (waiting), chef works on dish 2. When dish 2 is boiling (waiting), chef checks dish 1.

The chef never stands idle - always doing something useful!

How Async Event Loop Works
     EVENT LOOP (Single Thread)
     =====================================================
     
     Time ------------------------------------------------>
     
     Task A: [Run]--await--[Run]--await--[Run]--[Done]
                    |              |
                    v              v
     Task B:       [Run]--await--[Run]--[Done]
                          |
                          v
     Task C:             [Run]----------[Done]
     
     =====================================================
     Only ONE task runs at any moment, but we switch between
     them during "await" (when they're waiting for I/O)

Basic Async Example

import asyncio

# Define an async function (coroutine)
async def fetch_data(name, seconds):
    print(f"{name}: Starting...")
    await asyncio.sleep(seconds)  # Non-blocking sleep
    print(f"{name}: Done!")
    return f"Result from {name}"

# Main async function
async def main():
    # Create tasks (they start running)
    task1 = asyncio.create_task(fetch_data("RTC", 2))
    task2 = asyncio.create_task(fetch_data("JIRA", 3))
    task3 = asyncio.create_task(fetch_data("Azure", 1))
    
    # Wait for all tasks to complete
    results = await asyncio.gather(task1, task2, task3)
    print(results)

# Run the event loop
asyncio.run(main())
RTC: Starting... JIRA: Starting... Azure: Starting... Azure: Done! RTC: Done! JIRA: Done! ['Result from RTC', 'Result from JIRA', 'Result from Azure']

Key Async Concepts

# 1. async def - Defines a coroutine
async def my_coroutine():
    return "Hello"

# 2. await - Pauses and waits for result
result = await my_coroutine()

# 3. asyncio.create_task() - Schedule coroutine to run
task = asyncio.create_task(my_coroutine())

# 4. asyncio.gather() - Run multiple coroutines concurrently
results = await asyncio.gather(coro1, coro2, coro3)

# 5. asyncio.run() - Start the event loop
asyncio.run(main())

Real Async HTTP Example (with aiohttp)

import asyncio
import aiohttp  # pip install aiohttp

async def fetch_url(session, url):
    async with session.get(url) as response:
        return await response.json()

async def main():
    urls = [
        "https://api.example.com/rtc/123",
        "https://api.example.com/jira/456",
        "https://api.example.com/azure/789",
    ]
    
    async with aiohttp.ClientSession() as session:
        tasks = [fetch_url(session, url) for url in urls]
        results = await asyncio.gather(*tasks)
        print(results)

asyncio.run(main())

Important: Async Requires Async Libraries

requests.get() is blocking - it won't work with async!

You need async-compatible libraries like aiohttp, httpx, or asyncpg.

Pros

  • Very efficient for I/O-bound tasks
  • No thread overhead
  • No race conditions (single thread)
  • Can handle thousands of concurrent connections
  • Lower memory usage than threads

Cons

  • Requires async-compatible libraries
  • Can't use regular blocking code
  • "Viral" - async spreads through codebase
  • Steeper learning curve
  • Not good for CPU-bound tasks
